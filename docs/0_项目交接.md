# 项目交接：腕部相机 Eye-in-Hand GraspNet UR7e 复现

## 当前目标

本目录要完成一条独立的腕部相机抓取链路：

```text
腕部 RealSense RGB-D
  -> 中心矩形工作区掩码
  -> GraspNet-baseline HTTP 推理
  -> RTDE 读取当前夹爪 TCP
  -> T_base_cam_now = T_base_tcp_now @ T_tcp_cam
  -> R_base_grasp_as_tcp = R_base_grasp @ grasp_to_tcp_rotation_matrix
  -> 输出/执行 UR7e TCP 抓取点位
```

本工程不依赖 `reproduction/graspnet-baseline-in-ur7e` 的代码。需要的相机、掩码、GraspNet 客户端、RTDE、XML-RPC 和坐标变换逻辑已经放在本目录 `src/eye_in_hand_graspnet/`。

机器臂控制方式已经对齐 `reproduction/graspnet-baseline-in-ur7e`：Windows 侧启动本机 XML-RPC `get_target()` 目标服务，示教器 URP 持续轮询 `[x,y,z,rx,ry,rz,gripper]`，Windows 再通过 Dashboard 端口加载并启动该 URP。不要再配置“PC 主动调用机器人 `move_tcp` XML-RPC 服务”的旧模型。

## 主入口

无硬件烟测：

```powershell
python scripts\smoke_test_no_hardware.py
```

连相机、GraspNet 服务和 RTDE 后先干跑：

```powershell
python scripts\run_wrist_grasp_cycle.py --config configs\eye_in_hand_ur7e_wrist.jsonc --dry-run
```

实机移动必须显式使用：

```powershell
python scripts\run_wrist_grasp_cycle.py --config configs\eye_in_hand_ur7e_wrist.jsonc --execute
```

## 当前配置约定

- 腕部相机序列号：`419122270341`。
- 掩码：只保留图像中心宽高各 1/2 的矩形区域，其余 RGB 置黑、depth 置 0。
- 随机种子：`20260531`，通过 `graspnet.seed_field` 发送给 GraspNet 服务。
- 标定矩阵：`configs/eye_in_hand_calibration_tcp.jsonc/T_tcp_cam`。
- 默认 TCP 姿态策略：`grasp.tcp_rotation_mode = current`，先保持当前夹爪姿态，只验证位置链路。
- 默认 GraspNet 到 UR TCP 轴重排：`grasp.grasp_to_tcp_rotation_matrix`，对应 `UR TCP X/Y/Z = GraspNet Y/Z/X`。
- 默认 TCP 偏置：`tcp_translation_offset_m = [0,0,0]`，表示暂时假设 UR TCP 原点就是视觉抓取中心；实机前需要按夹爪结构复核。

## 实机前必须填写

`configs/eye_in_hand_ur7e_wrist.jsonc` 中的：

- `motion.fixed_start_tcp`：固定观察点位 `[x,y,z,rx,ry,rz]`，必须是现场低速确认过的安全观察位。
- `motion.xmlrpc_host` / `motion.xmlrpc_port`：Windows 侧 `get_target()` 服务监听地址和端口；示教器 RPC URL 必须指向 `http://<Windows_PC_IP>:<port>/RPC2`。
- `motion.dashboard_port`：UR Dashboard 端口，通常为 `29999`。
- `motion.grasp_program`：示教器中的轮询 URP 文件名，默认 `aaaaaa.urp`。
- `motion.enabled_steps`：执行步骤。首轮建议只保留 `start` 或 `pregrasp`，方向确认后再开放 `grasp`，最后才开放 `close`。
- `graspnet.url`：GraspNet HTTP 推理服务地址，当前默认 `http://127.0.0.1:18080/infer`。
- `grasp.grasp_to_tcp_rotation_matrix`：GraspNet 局部轴到 UR TCP 局部轴的基础映射；默认已经按当前夹爪约定填写。
- `grasp.tcp_translation_offset_m`：从 GraspNet 抓取中心到 UR TCP 原点的偏置，按最终 TCP 坐标系表达。

## 推荐调试顺序

1. 运行无硬件烟测，确认配置和坐标变换代码没有语法或基本逻辑错误。
2. 启动 GraspNet 服务，单独用 `--dry-run` 确认腕部相机能返回 `best_grasp`。
3. 检查输出的 `camera.serial` 必须是 `419122270341`。
4. 检查 `outputs/last_wrist_grasp_result.json` 中的 `T_base_cam_now`、`grasp_center_base`、`tcp_pregrasp`、`tcp_goal`。
5. 将 `templates/ur/aaaaaa_rpc_template.script` 逻辑复制到示教器程序，并把 RPC URL 改成当前 Windows PC IP。
6. 首次实机只允许移动到 `start` 或 `pregrasp`，低速、张开夹爪，不闭合。
7. 方向和高度确认后，再开放 `grasp` 步骤，最后才开放 `close`。

## 当前风险

- 当前 18080 服务使用 JSON 请求，大数组字段为 `.npy + base64` 编码；如果后续换成其它服务接口，需要同步调整 `graspnet.request_format` 或 `graspnet_client.py`。
- 如果示教器没有访问 PC 的 `get_target()`，优先检查 RPC URL、Windows 防火墙、PC IP 和 `motion.xmlrpc_port`。
- `tcp_rotation_mode=current` 能降低姿态风险，但不等于最终可抓取姿态；要跟随 GraspNet 姿态时，基础轴重排已经由 `grasp_to_tcp_rotation_matrix` 完成，现场残余修正再放入 `tcp_rotation_offset_matrix`。
- 标定结果绑定的是“夹爪 TCP”，如果示教器 TCP 定义再次变化，需要重新确认或重新标定。
